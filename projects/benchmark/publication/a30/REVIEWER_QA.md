# Expected reviewer questions and where the manuscript answers them (A30-11)

Section and table numbers refer to the A30 Applied Sciences PDF. "Limitation n" is item n of §6.2.

| Expected question | Short answer | Evidence in the manuscript |
|---|---|---|
| This is not a new model. What is the contribution? | A benchmark that reports both whether a detector runs and whether its top alerts are useful, including failed runs, plus a memory-saving implementation of a common loss checked at full scale. The DLG-GNN models are two of seven detectors, and we claim no superiority. | Contributions (§1), §3.3, Table 3 (dense vs memory-saving loss), Figure 3 (memory sweep), §5.1 and Table 2 (failures with causes), §5.4 |
| Is the "exact" loss really exact, or only close? | It is the same quantity computed in a different order. On nine benchmark graphs the training losses differ by no more than two dense runs from the same start, and the top-1% and top-5% alert lists are identical. | §3.3, §5.2, Table 3 |
| Why random splits and not temporal splits? | The graphs are static snapshots, and the split follows the primary protocol. A temporal split of Elliptic is the first candidate for an additional experiment. | Limitation 3 |
| Do PyGOD implementation details drive the conclusions? | CoLA ranks near random with the library code, while a compact re-implementation of the original design reaches ROC-AUC 0.93 on Cora-Syn. OCGNN embeddings collapse onto the centre. Equal-budget tuning does not separate the three reconstruction models (Friedman p = 0.61). | §5.5, Tables 7 and 8, Table A21, Limitation 5 |
| Are the default hyperparameters unfair to some detectors? | All detectors use the library defaults in the primary runs. Equal-budget tuning on six graphs is reported separately and changes AP by more than 0.005 in 32 of 42 cells, in both directions. | §5.5, Table A21, Limitation 4 |
| Did spilling past GPU memory distort the time comparisons? | Runs whose reserved memory exceeded the 24 GB card are marked and are not used for speed comparisons. Timed runs ran one at a time with a CPU-speed probe. | Table 4 footnote, Limitation 6 |
| Why are some detector–graph pairs missing? | 84 of 91 pairs completed. The seven failures involve AnomalyDAE (edge attention on Reddit-Syn needs one 27.4 GiB tensor) and GADNR (GPU out of memory, host RAM exhausted, or an illegal-memory-access error whose cause was not established). The retries are reported and the primary counts are unchanged. | §5.1, Figure 2, Table 2, Table 4 |
| AnomalyDAE on DGraphFin: did it fail or not? | It completed in the primary runs, which had no time cap (Table 5). It only reached the 3 h cap of the separate resource measurement. | §5.2 resource paragraph, Table 4 footnote |
| Why not compare with supervised fraud detectors? | Supervised models are a reference line that shows the labels carry signal (Elliptic AP 0.984). They are not competitors, because the study is about the unsupervised setting. | §5.8, Table 11 |
| Are synthetic anomalies representative of real fraud? | Partly not, which is why five graphs with real labels and their own edges were added. There, edges helped on two graphs and a feature-only detector won on the two review-fraud graphs. | §5.6, Tables 9 and 10, Limitation 1 |
| The blockchain graphs have constructed edges. | Yes: the edges are k-nearest neighbours in feature space. This is stated, and the conclusions about graph structure rest mainly on the real-label graphs. | §4.1, Limitation 2 |
| Weibo has 347 positives; BOND lists 868. | The distributed file holds 347 positives. Its edge count (407,963 directed entries) matches BOND, so only the label count differs. We use the file unchanged and say so. | Table 9 note |
| Can the results be reproduced? | Aggregate results, scripts and the pre-registered protocol are archived under fixed tags. The PDFs build byte-identically from the source bundles. Per-node scores and labels stay with the authors because of the dataset licences. | Data Availability Statement, `publication/a30` |
| How was generative AI used? | For code, orchestration and statistics checks, and for language editing. Every reported number was produced by the scripts and verified by the authors. | §4.5, Acknowledgments |
