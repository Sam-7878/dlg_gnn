독립 검토에서 **기존에 보지 못한 더 중요한 항목**이 확인됐습니다. 논문의 Table 1과 Table 2가 같은 데이터셋의 `Test Prevalence`를 서로 다르게 쓰고 있으며, 특히 A08 암호화폐 실행 레지스트리에는 실제 시드별 평가 양성률이 별도로 기록돼 있습니다. 이는 AP의 무작위 기준선 해석에 직접 영향을 주므로, 단순한 보고서 오타보다 우선 해결해야 합니다.

반면 A14의 핵심 목적이었던 **Figure 3–Table 4 일치, 455개 승인 실행 선별, 제출 ZIP의 원고 일치**는 실제 파일에서도 확인됐습니다. 추가 학습 없이 마무리할 수 있도록 마지막 수정 범위를 좁혀 문서화하겠습니다.


A14 실행 보고서와 업로드하신 **`scripts.zip`, `a14.zip`, `a14_paper.zip`, `submission.zip`**을 독립적으로 검토했습니다. 실제 455개 실행 레지스트리, 70개 시드별 AP 차이, 논문 LaTeX, PDF, 제출 ZIP의 SHA-256 및 공개 GitHub 태그까지 대조했습니다.

## 2. 가장 중요한 문제: Test Prevalence

실제 A14 논문의 Table 1과 Table 2를 비교했습니다.

| 데이터셋       | Table 1 양성률 | Table 2 무작위 AP 기준선 | 승인 실행 기록의 평가 양성률 |
| ---------- | ----------: | -----------------: | ---------------: |
| Ethereum   |      0.4184 |             0.0195 |       **0.4089** |
| BSC        |      0.1476 |             0.0210 |       **0.1473** |
| Polygon    |      0.0261 |             0.0052 |       **0.0259** |
| BitcoinOTC |      0.0300 |             0.0890 |         별도 확인 필요 |
| DGraphFin  |      0.0127 |             0.0134 |         별도 확인 필요 |

암호화폐 세 데이터셋은 승인된 A08 실행 레지스트리에 평가 대상 노드 수와 양성 노드 수가 시드별로 기록되어 있어 직접 계산할 수 있었습니다.

예를 들어 Ethereum의 실제 평가 양성률 평균은 약 **40.89%**입니다.

따라서 DLG-Aug의 AP가 0.4359라면, 0.0195가 아니라 **같은 평가 집단의 양성률을 기준으로 해석해야 합니다.**

이 차이는 논문에서 탐지 성능의 실용적 의미를 평가하는 데 중요합니다.

원본 그래프의 양성률과 실제 테스트 집단의 양성률을 혼동했을 가능성이 있습니다. A15에서는 이 둘을 분리하도록 했습니다.

**새 모델 학습은 필요하지 않습니다.** 평가 마스크와 라벨 수를 확인하면 해결할 수 있습니다.

## 3. 그 밖에 발견한 문제

### A14 실행 보고서에 잘못된 결과표가 포함되어 있습니다

실제 논문 Table 4는 올바르게 수정됐습니다.

하지만 실행 보고서의 *Final Harmonized Delta Table*에는 실제 Benchmark에 없는 **Tolokers, Questions, T-Finance, T-Social, YelpChi**가 등장합니다.

또한 Ethereum, BSC, Polygon의 Base/Aug AP 수치도 실제 승인 CSV와 다릅니다. 

이는 논문 자체보다 **실행 보고서의 오류**입니다. 반드시 바로잡는 것이 좋습니다.

### 실행 지원 설명도 수정해야 합니다

실제 승인 레지스트리에서 미지원된 7개 조합은 다음과 같습니다.

* GADNR: 5개 데이터셋
* AnomalyDAE: 2개 데이터셋

그런데 현재 원고에서는 GADNR이 7개 데이터셋에서 실패했다고 설명하면서 AnomalyDAE의 2개 실패를 별도로 기술합니다.

총 지원 결과인 **84/91은 맞지만, 실패 모델별 분류 설명은 틀립니다.**

### GitHub 태그는 실제로 존재합니다

이전 A13과 달리 이번에는 공개 GitHub의 A14 태그를 확인할 수 있었습니다.

다만 현재 태그의 실제 대상 커밋은 다음과 같습니다.

`19442b4612dcd5dca3c5cdef5a8b37575cabd5db`

실행 보고서에 기재된 `b9e417...`, `bd06fd...`와 다릅니다.

또한 업로드된 실제 PDF와 ZIP의 해시는 내부 `SHA256SUMS.txt`와 일치하지만, **실행 보고서에 적힌 SHA-256은 이전 버전 값**입니다.

즉 파일 자체가 손상된 것은 아니지만, 보고서와 릴리스 확인 기록을 갱신해야 합니다.
